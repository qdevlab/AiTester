# Переносимость: как навести тулу на другую цель

Тула не сшита с целью — доказательно: в коде (`harness/**.py`) нет литералов цели (порты,
cus-номера, имена коллекций, пути ручек, realm/secret живут ТОЛЬКО в `config/`). Проверка:

```bash
grep -rnE '9600|37017|genai-stand|streamlit-ui|agent_policy_memories' source/harness --include=*.py \
  | grep -vE '/config|__main__|docstring|#'
# -> совпадения только в комментариях/смоуках/тексте findings, не в логике
```

## Процедура переноса (замена одного файла)

1. **`customer_info.md`** новой цели (от заказчика) — прозаическое описание.
2. Собери из него **`config/target.yaml`** по той же схеме (endpoints / auth_modes / provisioning
   / finalize_triggers / storage / tools / identities+эталон / target_models). Это единственный
   обязательный файл для перенастройки — весь код читает отсюда через `core/config.py`.
3. При необходимости адаптируй **`hypotheses.yaml`** (участники/оси свипа) и **`payloads.yaml`**
   (регистры формулировок под домен новой цели).
4. Запусти `smoke` → `bac`/`poison`. `findings.json` самодостаточен для повтора на другом агенте.

Чего нет в customer_info — помечай `needs_review` в `target.yaml`, НЕ выдумывай.

## Уровни детекта и деградация на black-box

Тула работает на трёх уровнях доступа; чем меньше доступ — тем слабее (но не нулевой) детект:

| Доступ | BAC | Отравление памяти |
|---|---|---|
| **grey-box** (redis/mongo на host) | дифф ярусов + прямое чтение | трейс-файл трейсера + Q&A (осн.); при grey-box возможен и прямой дифф `policy`/`semantic` — сильнейший |
| **api-box** (только HTTP цели + провижининг) | `served_cross_cus` на data-service токеном атакующего; отпечатки в ответе агента | ответ finalize (scope/факты), `GET /memory`, отпечатки в ответе жертвы |
| **black-box** (только чат-ручка) | отпечатки жертвы в ответе агента (agent_mediated) | маркер в ответе жертвы после finalize (воспроизведение), дифференциально |

Режим детекта фиксируется в находке: grey-box даёт пруф по состоянию, black-box — более слабый
по наблюдаемым признакам. «Не воспроизведено на black-box» ≠ «безопасно» (см. anti-goals ТЗ).

Для этой цели grey-box доступен (redis:16379/mongo:37017 проброшены) → используем сильнейший
детект. `GET /memory` требует SSO-токен oauth2-proxy (headless-путь не описан) — помечено
`needs_review`; при отсутствии grey-box переключились бы на api-box/black-box признаки.

## Что переносимо как есть, что зависит от цели

- **Переносимо (механика):** транспорт, headless-провижининг (шаблон grant→mint→cache),
  state-оракул (чтение ярусов по именам из конфига), мульти-отпечаток, изоляция, LLM-атакующий,
  дифф-судья, отчёты. Ни одной правки кода.
- **Из конфига (факты цели):** адреса/пути ручек, способ выдачи ключа, имена хранилищ/коллекций,
  список инструментов, тестовые идентичности+эталон, строки моделей, лимиты подмешивания.
