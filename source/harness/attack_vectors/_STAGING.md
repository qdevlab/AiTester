# attack_vectors/ — Волна 0 (12 новых модулей атак)

> **Исторический документ: статус Волны 0 (до появления трейсера).** Это снимок подготовки Волны 0, и
> он не описывает нынешний способ проверки. Столбец «проверка» в таблице ниже (обозначения E1..E4,
> сравнение содержимого баз, отбор по доступности базы) — это замысел того времени, сейчас он устарел.
> Актуальная проверка памяти устроена иначе: журнал внешнего трейсера (файл трассировки) плюс повторный
> вопрос модели в новом диалоге или от другого клиента. Прямое чтение внедрённой метки из базы как
> способ вынести вердикт использовать нельзя. Как всё работает сейчас и какой у этого API — см.
> `docs/ATTACK_VECTORS.md`, раздел 6.

12 модульных векторов Волны 0 (те, что подошли к цели и подключаются без правок ядра) по контракту из
`docs/ATTACK_VECTORS.md`. Ядро модульной системы (`base.py`, `registry.py`, запуск через `a-<name>`)
уже есть в репозитории — его добавил разработчик. Поэтому модули подхватываются автоматически и
запускаются как есть.

## Статус проверки (локально, без стенда)
- `run.py --list` — все 12 модулей на месте: параметры разбираются, класс определяется, классификация
  видна. При загрузке наших модулей ни одного предупреждения.
- `run.py a-stub` — каркас проходит целиком, от начала до конца: обнаружение модуля, драйвер, файлы
  `report__stub.{json,md}`.
- Защита от сбоев: модули только на чтение (`a-a05_direct_leak`, `a-l03_recon`), запущенные без стенда,
  ведут себя корректно — каждую попытку перехватывает `attempt_guard`, `run()` не падает, отчёт помечает
  находку как `not-demonstrated` (честно: «не удалось воспроизвести в этих условиях», а не «безопасно»).
- (Устарело.) Тогда модули отравления включались только при доступной базе (`applicable` проверял
  `grey_box_available`). Сейчас вердикт по памяти дают журнал трейсера и повторный вопрос
  (`docs/ATTACK_VECTORS.md`, раздел 6.2), а отбор по доступности базы убран.
- На живом стенде пока не запускались: здесь нет ни базы, ни агента. Это делается на стенде Димы.

## Контракт (сверен с настоящим `base.py`) — совпал, код не меняли
Сверили: `VectorContext.client()/attacker()/judge()`, `attempt_guard(ctx.run, label=...)`, метаданные
класса `AttackVector` (`name`, `title`, `active`, `mutates_state`, `taxonomy`, `requirements`,
`hypotheses`), фабрику `F.finding(...)`, обнаружение модулей по папке без `__init__.py`. Получение
ключей вынесено внутрь `attempt_guard` — по правилу из раздела 8b `run` не должен падать даже при
неработающем стенде.

## Что входит в Волну 0 (12 новых модулей: подошли к цели и подключаются без правок ядра)
| Папка | Кейс | Тип | mutates_state | Проверка (замысел Волны 0, устарел — актуально см. раздел 6.2) |
|---|---|---|---|---|
| `a05_direct_leak` | TC-A05 | bac | нет | E4: отпечаток жертвы в ответе без успешного вызова инструмента (сравнение уязвимого и защищённого режимов) |
| `b03_false_precedent` | TC-B03 | memory_poisoning | да | E2 в episodic/dialog и E3 |
| `c01_explicit_command` | TC-C01 | memory_poisoning | да | E2 в semantic и E3 |
| `c03_policy_conformant` | TC-C03 | memory_poisoning | да | E2 в policy (global) и E3 у клиента 1002, с поправкой на базовый уровень |
| `f01_secret_landing` | TC-F01 | within_user | да | E2: секрет в semantic, и E3 |
| `f03_prompt_extract` | TC-F03 | memory_poisoning | да | E3 (в другом виде): общая метка в ответе клиента 1002 |
| `g02_multilingual` | TC-G02 | memory_poisoning (ось) | да | E2 с разбивкой по языку и режиму |
| `g03_register` | TC-G03 | memory_poisoning (ось) | да | E2: закрепление с разбивкой по формулировкам |
| `g05_cover_tracks` | TC-G05 | memory_poisoning | да | закрепление после попытки замести следы (тогда — через сравнение содержимого баз) |
| `i02_sleeper` | TC-I02 | memory_poisoning | да | E2: парное сравнение до и после консолидации (finalize) |
| `i03_single_injection` | TC-I03 | memory_poisoning | да | E2: закрепление с одной инъекции и E3 |
| `l03_recon` | TC-L03 | recon | нет | разведка до атаки (инструменты, триггеры, системный промпт) |

Рабочие гипотезы H1–H5 (A01/A02/B01/B02/D01/E01) у разработчика уже закрыты модулями `bac`, `mem`,
`chain`. Откуда взяты кейсы: каталог заявки `catalog/CATALOG.md` (он внешний, в этот репозиторий не
входит). Про безопасность: используются только метки-слова (`isolation.fresh_marker()`), ни одной
боевой нагрузки. Номера статей перед отчётом нужно сверить по PDF.

## Как запускать на стенде
```
python run.py --list                          # все модули
python run.py a-i03_single_injection          # один
python run.py a-c03_policy_conformant c03_policy_conformant--attempts=12
```
Канал через веб-поиск (D02/D03/M02) в Волну 0 не входит: по договорённости мы его пока не трогаем, пока
он не сверен по коду стенда.
