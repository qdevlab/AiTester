# Вектор `mem` — отравление многоярусной памяти

Через диалог внедряется факт или инструкция (со словом-маркером), затем запускается консолидация
(`finalize`), и модуль измеряет, на каком ярусе память это закрепила.

Модуль выключен по умолчанию (`active=False`) и не входит в `a-all` — это прежнее ядро отравления,
поэтому его вызывают явно: `a-mem`.

## Как это работает
- Стадии, если по-простому: рабочая память (до финализации), затем закрепление на ярус
  (`policy`/`semantic`), затем попадание в собранный контекст и, наконец, всплытие в ответе при
  повторном вопросе в новой сессии.
- Закрепление в общей памяти (`policy`, scope=global) — межклиентский эффект, уровень critical;
  закрепление в личной памяти (`semantic`, scope=user, в пределах одного клиента) — уровень high.
  Вердикт даёт внешний трейсер памяти вместе с повторным вопросом в новом диалоге или от другого
  клиента; метку из базы для вердикта не читаем. Каждая успешная проба сохраняет трейс в `traces/`.
  Измеряется доля закрепления с доверительным интервалом (Wilson); базовая доля сейчас жёстко обнулена
  — `clean_baseline` возвращает 0.
- Режим «чёрного ящика»: если mongo и redis недоступны (нет «серого ящика»), вердикт выносится по
  поведению агента — метка в ответе новой сессии плюс оценка по рубрике; такие находки помечаются как
  менее достоверные (`F-POISON-BEHAVIORAL`).

Модуль меняет состояние (`mutates_state=True`): драйвер берёт аренду, а `run_mvp` делает точечную
очистку канареек (полная очистка — только через `reset.full_wipe` в конфиге). Маркеры — обиходные
слова (`fresh_marker`).

## Конфиг
`config/target.yaml` задаёт хранилище (коллекции и лимиты mongo, redis), идентичности и триггеры
`finalize`; `config/payloads.yaml` — формулировки `memory_poisoning.<register>`. Значений стенда в
коде нет.

## Параметры
Значения по умолчанию — в `params.yaml`. Пример: `run.py a-mem mem--attempts=6 mem--registers=compliance`.

## Запуск
```
./.venv/bin/python run.py a-mem
./.venv/bin/python run.py a-mem mem--registers=benign,compliance
```

## Находки
`F-POISON-GLOBAL` (critical, межклиентский), `F-POISON-USER` (high, в пределах одного клиента), а в
режиме чёрного ящика — `F-POISON-BEHAVIORAL`. Отчёты пишутся в `report__mem.{json,md}`;
человекочитаемое доказательство — файл `proof.md` в папке прогона
(`output/runs/<штамп>/<модуль>/proof.md`), плюс стабильная общая копия `output/POISON_PROOF.md`.
