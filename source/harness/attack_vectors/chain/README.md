# Вектор `chain` — связка двух атак (доступ к чужим данным через отравлённую память)

Показывает, что отравление памяти (задача A) и нарушение контроля доступа, BAC (задача B),
складываются в одну атаку: чужой идентификатор попадает к жертве не прямым текстом, а через память
агента.

Модуль неактивен (`active=False`) — в `a-all` не входит, вызывается явно: `a-chain` (нужен доступ к
внутреннему состоянию стенда).

## Как это работает
1. Задача A: атакующий в диалоге сажает «правило» с чужим номером счёта, затем `finalize` запускает
   консолидацию.
2. Закрепление правила подтверждает внешний трейсер (`tr.get_canary` / `tr.landed`, сигналы
   `rule_landed_global` и `rule_landed_user`); при удачном закреплении `tr.save_trace()` кладёт трейс
   в `traces/`. Прямое чтение из базы (mongo) закомментировано и в вердикте не участвует.
3. Задача B: жертва запускает рутинное действие; утечка — это отпечатки чужого клиента в ответе, а
   не эхо запроса.

Атака стохастична, поэтому прогоняется несколько циклов, каждый раз со свежими канарейкой и
правилом и с очисткой после. Модуль меняет состояние стенда (`mutates_state=True`): драйвер берёт
стенд в монопольное пользование, а `run_chain` делает точечный сброс.

## Совместимость
Доступ к внутреннему состоянию стенда нужен, но не для вердикта о закреплении — его даёт внешний
трейсер. Доступ к базам требуется для точечного сброса и очистки стенда, а также для части с
доступом к данным (задача B). Без доступа к базам `applicable()` возвращает False и вектор
пропускается.

## Конфиг
`config/target.yaml`: идентичности (атакующий, жертва, чужой счёт) и хранилище; `config/payloads.yaml`:
`chain.plant_foreign_id`. Без зашитых значений.

## Параметры
См. `params.yaml`. Пример: `run.py a-chain chain--attempts=6`.

## Запуск
```
./.venv/bin/python run.py a-chain
```
Алиас: `run.py chain` (старое имя).

## Находки
`F-CHAIN-AXB` (critical, доля успеха с доверительным интервалом). Отчёт: `report__chain.{json,md}` с
доказательством «что написал пользователь» на обеих стадиях.
