# Вектор `chain` — связка A×B (BAC через отравлённую память)

Демонстрирует, что отравление памяти (Таск A) и BAC (Таск B) складываются в одну атаку: чужой
идентификатор доставляется жертве НЕ прямым текстом, а через память агента.

**`active=False`** — не входит в `a-all`, зовётся явно: `a-chain` (требует grey-box).

## Как это работает
1. **A**: атакующий диалогом сажает «правило» с ЧУЖИМ счётом → `finalize` (консолидация).
2. Оракул проверяет приземление правила на ярус (`marker_landed_global/user`, mongo).
3. **B**: жертва триггерит рутинное действие; утечка = отпечатки чужого клиента в ответе (не эхо).

Стохастично → N циклов, свежая канарейка/правило, teardown после каждого. State-меняющий
(`mutates_state=True`): драйвер берёт lease; `run_chain` делает точечный сброс.

## Совместимость
Требует **grey-box** (проверка приземления правила по mongo). Без БД — `applicable()=False`, вектор
пропускается.

## Конфиг
`config/target.yaml`: identities (attacker/victim/чужой счёт), storage; `config/payloads.yaml`:
`chain.plant_foreign_id`. Ноль литералов.

## Параметры
См. `params.yaml`. Пример: `run.py a-chain chain--attempts=6`.

## Запуск
```
./.venv/bin/python run.py a-chain
```
Алиас: `run.py chain` (старое имя).
